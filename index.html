Approach

How I think about AI products

⬡
User pain first
Problem definition

I start with the unmet need, not the model. The technology is the delivery mechanism — the problem is the product. Build backward from friction, not forward from capability.

⬡
Build the feedback loop
RLHF × product design

Every AI product I design has a built-in learning loop. User actions are training signals. An AI that improves with every use is a product with compounding value — that's the moat.

⬡
Eval before launch
ROUGE · BLEU · HELM

I define evaluation metrics before writing a single line of model code. For Lovebirds Lens, 85% accuracy was the launch gate — not a post-hoc achievement. Measure first, ship second.

⬡
Ship small, iterate fast
AI lifecycle management

LoRA over full fine-tuning. RAG over retraining. PEFT over parameter explosion. The smallest intervention that solves the problem, shipped fast, beats perfect architecture deployed late.
